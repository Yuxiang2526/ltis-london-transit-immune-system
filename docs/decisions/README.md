# Architecture Decision Records (ADRs)

Each ADR captures a non-obvious design or methodological choice, the alternatives considered, and the consequences accepted. They exist so:

- a future reader (or marker) can audit *why* the project ended up this way, not just *what* it ended up as;
- when a decision is revisited, the rationale isn't lost.

## Format

Each ADR follows: **Context → Decision → Reasoning → Consequences → Alternatives / References**. New ADRs should number sequentially and be added to the index above.
